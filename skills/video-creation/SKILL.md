通过 `promptframe` MCP 使用平台的当前工具目录。外部客户端提供自己的推理；平台不另起网页导演。先确认用户要做的作品、项目和已有事实，避免重复制作与收费。

## 连接与选择作品

未连接时先按 creation-setup Skill 和 Studio 当前固定版本指引运行 `connect`，提供用户选择的平台 API 地址。`setup` 只处理凭据，不能代替插件注册。凭据只交本地连接流程的安全输入，不写聊天、源码、命令行参数或 MCP 业务参数。创作 Token 与组件上传凭据用途不同，也不是 OAuth `mcp login`。

使用平台项目和作品列表选择目标。新作品使用稳定的幂等请求键；已有作品先读取最新历史、Plan、Spec、素材和在途任务，再申请编辑权，由本人在 Studio 确认。不要修改已有作品的运行时来换端。断线和思考不代表释放编辑权。

首次进入项目，在创建作品前先发现并读取 `platform_read_onboarding`：它返回平台当前发布的公开创作基线、版本摘要和公开合同导航，只需项目读取权，不创建作品、执行或制作任务。完整基线只维护在平台；两端同版本正文与摘要应一致。按“接入检查→公开基线→当前公开合同→按需专题”阅读，再选择现成组件或下方既有组件作者工具链。平台尚未提供该读面时说明缺件，不为读说明先新建作品或猜内部 Skill。

作品读取默认返回一页历史和当前文档的版本/摘要，不代表完整历史或完整 Spec/Plan。需要正文时，按平台当前 schema 显式选择所需文档；更早消息沿返回的游标继续读取。引用单条消息或原工具调用时使用其稳定身份，不把近期页当全历史，也不为补读重派业务。

## 准备与方案

先复用已有素材和合适的已受检组件。外部客户端可用自己已有的调研、图像或本地创作能力，平台外用量不冒作平台计费；不要为省步骤而重复生成已经完成或结果未知的订单。

组件也是视频表达手段：从平台当前工具目录发现组件检索、详情与 schema 读取能力，按真实 schema 构造 props，并使用平台返回的 `componentRef`。组件 CLI 的 `discovery` 和 `component list` 分别是端点能力与项目声明读面，不作为市场搜索的替代。

确需新组件时，阅读独立的 [组件创作 Skill](https://github.com/ty-teams/promptframe-component-authoring/blob/main/skills/component-authoring/SKILL.md)、[工具链 README](https://github.com/ty-teams/promptframe-component-authoring#readme) 与 [Authoring Guide](https://github.com/ty-teams/promptframe-component-authoring/blob/main/AUTHORING.md)，按需使用 `@promptframe/cli`、`create-promptframe-component`、`@promptframe/component-kit` 和 `@promptframe/contracts`。在独立作者项目中开发，按当前标准选择兼容版本；经本地检查/预览、上传及平台构建审核确认可用后，再读取组件身份、版本和 schema 接回作品。上传受理、本地预览或 npm 包名不代表平台组件已就绪。

CLI 的端点与组件上传授权按其公开说明配置，创作 Token 不代替组件凭据。可复用组件走 `marketplace_authoring`，项目私有组件走 `project_private_generation`，遵循用户用途及平台权限；组件开发或上传不代替本人制作确认。具体 CLI 命令由其维护中的文档提供，不在本 Skill 复制参数手册。

用平台的 brief 上报能力保存外部需求/交接说明，明确是客户端上报。没有上报的外部聊天、思考或本地代码仍未知，不能伪造为平台历史或用户已确认原话。

读取当前业务目录与 exact schema 后调用工具，不在本 Skill 维护参数副本。CreativePlan 独立创建/读取/修改，保留完整需求、导演方案和可信来源。其它业务调用引用已保存的方案，不夹带另一份 Plan 或反向覆盖它。

普通 Skill 目录与说明读取不等于真实采用版本。`skill_view` 的 view/none 是说明读取；只有当前执行确实采用时才按原合同显式 use，不能为读取正文创建制作任务或伪造使用回执。长任务仍按原 task 身份和期限观察。

上传自有素材后，等平台确认受管状态 ready，并使用返回的稳定 assetRef。文件路径、外部下载地址和“已上传”提示不能替代资产就绪。外部自己生成的图片不会凭上传自动产生平台原生图服务费。

## 开工、费用与异步

正式制作需要已保存 Plan 和平台本人点击开始。把平台返回的确认状态与准确 Studio 入口交给用户；工具参数、已打开网页和 URL 都不能代为批准。批准后由当前外部客户端继续，不启动第二个网页导演。

宿主自动提供当前 Codex thread 身份，薄桥按本线程已获批准的编辑权携带 controlVersion；不要在工具参数中自行填写或猜测 threadId、controller、Token 或 controlVersion。作品 revision 仍须按真实读取结果用于原业务并发检测，薄桥不会替你填最新内容版本。失权后停止新派发和写入，重新读事实并按需申请由本人在 Studio 确认；不要把旧整份 Spec 覆盖当前作品。原 task 仍用原身份查询，不借接管重派。预算沿同一作品的原有段，不把换工具、换端或新 task 当作重置额度。

长工具返回持久 task ID；保存它和原订单身份，用有上限的 wait/状态读取接续。RPC 结束或没再 poll 都不取消原订单。网络结果不明时先查询原 task，重试用同一个幂等键，不自动重派。保留原输入、期限和未知事实。

费用以平台原 receipt/账务读面为准，区分实计、预留、待结算和未知。成功媒体、工具终态和财务终态可以不同；未知不是免费。平台工具调用与外部自费推理/素材费用分开说明。

## 旁白与字幕

整篇旁白先发现当前平台的规划与绑定工具，提交完整正文并核其真实能力限制。平台支持时，默认按句/段语义规划，短旁白可整段；音频段、字幕行和分镜不必一一对应。按计划使用同一音色版本及公共参数，每个合成调用只对应一个明确段和原报价。

保存每段原文范围、有效发声文本、原计划及已采用资产/operation。局部改文案沿原计划保持音色版本、seed 和公共参数，优先复用未改的成功段；结果未知只核原任务，不能重新生成追结果。字幕分块、样式或时序修复只绑定现有音频，不重TTS；仅凭时长估算仍标明estimated，不能冒精确逐字时间。当前目录未提供相关工具时准确说明限制，不在客户端另建合成队列或参数副本。

## 接回与完成

交接前可保存简明外部报告，随后释放自己当前代次的编辑权。没有报告也不阻止本人从 Studio 接回。旧订单可按原事实收尾、晚结果入素材与原账；旧客户端不能覆盖新 Spec。

把平台返回的 `studioUrl` 原样交给用户，创建、作品读取和交接共用服务端地址。仅在用户要求且宿主确实支持时打开；不要从本机路径、Token、请求头或其它环境拼链接。打开不启动网页导演、不批准制作，也不自动接管编辑权。

反馈只描述实际可见文字、工具结果、媒体就绪和导出状态，不补写模型思考或虚构进度。完成时核方案、素材引用和真实输出；需要云端 MP4 就等平台输出 ready，再把可访问结果交给用户。技术完成与本人视听验收分别说明。
