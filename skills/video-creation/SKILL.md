# 在 PromptFrame 创作

使用当前连接的 `promptframe` MCP。客户端提供推理，平台管理作品、素材、持久任务、权限与用量。未连接时使用 creation-setup；已有可用连接不需要重复安装或更换 Token。

## 先读当前公开指引

先从实时工具、resources 或 prompts 目录发现项目入门，读取当前账号与项目可见的公开创作基线。标准资源只使用平台目录返回的 URI；支持 prompt 时使用其声明的参数。旧入口可使用目录中的 `platform_read_onboarding`，无需先创建作品或执行制作任务。

按返回的版本、正文摘要和公开合同导航开展创作；需要详细规则时继续读取相关主题，不从插件版本推断平台工具或参数。目录变化通知可更新可见工具；宿主未刷新时可用现有通用调用入口，并先读取目标的当前 schema。能力缺失时说明具体版本或原因，不猜内部工具、文件路径或权限。

## 接续同一作品

先明确用户要新建还是接续已有作品。使用项目和作品目录确定唯一目标；歧义名称先让用户选择。已有作品读取当前 Plan、Spec、素材、版本和在途任务，必要时沿游标补历史，不把一页结果当全历史。仅按用户意图创建新作品。

开始制作和编辑权交接由本人在 Studio 确认。使用平台返回的准确作品链接和状态；打开网页、工具参数或客户端推断不能代替确认。外部客户端继续同一作品，不另启网页导演。

宿主提供聊天身份，桥管理作品控制代次。不要在业务参数或 `_meta` 中填写身份、Token、controller 或 controlVersion。内容修改使用实际读取的 revision；失去编辑权后停止新写入，先读事实，按需要重新申请交接。恢复会话能否保留身份以宿主和平台实际结果为准。

## 制作与观察

按平台当前公开基线完成方案、素材、Spec、场景及旁白/时间线绑定。优先复用同作品已就绪素材；路径、外链或“已上传”文字不能代替平台返回的可信资产引用。真实时间尚未取得时保留平台的估计等级，不把估时写成精确对齐。

用户指定本机素材时，先核当前目录是否提供本机上传能力。只读取用户明确指明的单个文件，说明桥实际运行在哪台机器；远程桥看不到桌面文件时直接说明，不能把 Hosted 沙箱的 `local_path` 当作用户文件。沿平台目录的本机上传入口流式直传，保存原幂等键，用同一键查询、恢复或取消。断线或完成回执未知时观察原会话，不另建上传或重传未知分片。进度100%、校验通过和素材ready是不同状态；只有原平台返回的稳定资产在同项目就绪后才接入作品，不因此夺取编辑权或开始制作。

保存异步调用的 task、operation、幂等键和原期限。已受理或结果未知时只沿原身份观察，不因断线、等待超时、升级或切端重新生成。调用结果、可用素材、Spec 采用和费用分别读取；缺少费用事实不代表零费用。确认未受理后，才能按公开错误指引修正新请求。

图片、音频和资源按宿主支持的标准内容显示；文字降级不能代替看过图片或听过音频。制作完成后按当前工具检查代表帧、播放和导出；下载、解码、有声音轨、字幕同步及真人听感分别记录结果。

## 需要自定义组件时

先在平台目录检索现成组件并读取 schema，使用受管 `componentRef`。确需新组件时，按[组件创作 Skill](https://github.com/ty-teams/promptframe-component-authoring/blob/main/skills/component-authoring/SKILL.md)、[工具链 README](https://github.com/ty-teams/promptframe-component-authoring#readme)与[Authoring Guide](https://github.com/ty-teams/promptframe-component-authoring/blob/main/AUTHORING.md)在独立作者项目开发。平台构建与授权就绪后再接回作品；本地文件、npm 包名和上传受理不是可用组件身份。组件上传凭据与创作 Token 用途不同。
